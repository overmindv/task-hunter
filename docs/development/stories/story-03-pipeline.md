# Story 3: Pipeline — базовый пайплайн обработки

**Для чего:** Реализовать инфраструктуру пайплайна: интерфейсы процессоров, оркестратор, extractor, parser, normalizer, validator.

---

## Task 3.1: Реализовать интерфейсы и оркестрацию пайплайна

**Для чего:** Создать пакет `internal/parser/pipeline` с абстракциями процессоров и оркестратором, последовательно прогоняющим RawTask → Task.

**Подробное описание:**

1. Создать директорию `internal/parser/pipeline/`
2. Определить интерфейс `Processor`:
   - `Process(ctx context.Context, raw domain.RawTask) (domain.Task, error)`
3. Определить интерфейс `Middleware` (опционально):
   - `Process(ctx, task) (domain.Task, error)` — модификация задачи между этапами
4. Реализовать структуру `Pipeline`:
   - Хранит список `[]Processor`
   - Метод `AddProcessor(p Processor)` — добавляет в конец
   - Метод `Run(ctx, raw) (domain.Task, error)` — вызывает процессоры последовательно
   - Если процессор вернул ошибку — пайплайн останавливается
   - Логирование каждого этапа через `slog`: начало, конец, длительность
5. Добавить структуру `Result`:
   - `Task domain.Task`
   - `Duration time.Duration` — общее время обработки
   - `Stages []StageResult` — результаты по этапам
6. Реализовать фабрику `NewDefaultPipeline() *Pipeline`, собирающую стандартную цепочку

**Тесты:**
- **Unit:** Pipeline.Run прогоняет через все процессоры по порядку
- **Unit:** ошибка в середине останавливает цепочку
- **Unit:** пустой пайплайн возвращает ошибку

**Сторипоинты:** 2

## Task 3.2: Реализовать извлечение и парсинг текста задачи

**Для чего:** Создать процессоры Extractor (извлечение контента из формата источника) и Parser (разбор текста на структурированные поля).

**Подробное описание:**

1. Создать `pipeline/extractor.go`:
   - `Extractor` реализует `Processor`
   - `Process(ctx, raw)`:
     - В зависимости от `raw.Source.Type`:
       - `SourceTypeTelegram` — извлекает текст сообщения и медиа
       - `SourceTypeWebsite` — очищает HTML, оставляет Markdown-подобный текст
       - `SourceTypeAPI` — десериализует JSON/XML
     - Возвращает `RawTask` с очищенным текстовым содержимым
   - Использовать `goquery` для работы с HTML
2. Создать `pipeline/parser.go`:
   - `Parser` реализует `Processor`
   - `Process(ctx, raw)`:
     - Пытается выделить **заголовок** (первая строка / до `##`)
     - Извлекает **условие** (основной текст)
     - Ищет **примеры** по шаблонам: `Input: ... Output: ...` или `Ввод: ... Вывод: ...`
     - Ищет **ограничения**: через маркеры `Constraints:`, `Ограничения:`, `1 ≤ N ≤`
     - Заполняет `SourceURL` из `raw.SourceURL`
   - Если что-то не найдено — не ошибка, поле остаётся пустым
3. Создать папку `testdata/parser/` с golden-файлами для тестов

**Тесты:**
- **Unit (golden):** парсинг текста со всеми полями (заголовок, условие, примеры)
- **Unit (golden):** парсинг текста только с условием (без примеров)
- **Unit (golden):** парсинг пустого текста — валидная ошибка
- **Unit (golden):** extractor для HTML-страницы LeetCode (заглушка/sample)
- **Unit (golden):** extractor для HTML-страницы Codeforces
- **Unit (golden):** extractor для JSON от API

**Сторипоинты:** 3

## Task 3.3: Реализовать нормализацию и валидацию задачи

**Для чего:** Создать процессоры Normalizer (приведение к единому формату Markdown) и Validator (проверка целостности).

**Подробное описание:**

1. Создать `pipeline/normalizer.go`:
   - `Normalizer` реализует `Processor`
   - Логика:
     - Trim лишних пробелов и переносов строк
     - Приведение к единому Markdown-формату:
       - Заголовки: `### Заголовок` → `## Заголовок`
       - Код: обернуть в ` ``` ` если есть инлайн `code`
       - Примеры: формат `**Ввод:** ...` → `**Input:** ...` (единый язык)
     - Удаление пустых примеров
     - Сортировка тегов по алфавиту
     - Обрезка слишком длинных полей (лимит конфигурируемый)
2. Создать `pipeline/validator.go`:
   - `Validator` реализует `Processor`
   - Логика:
     - Проверка `Description != ""` (обязательное поле)
     - Проверка `SourceURL != ""`
     - Проверка `SourceHash != ""` (если нет — генерирует)
     - Проверка Source.ID валидный (известный SourceID)
     - Проверка длины полей (не длиннее лимита)
     - Валидация через `task.Validate()`
   - Возвращает ошибку, если валидация не пройдена

**Тесты:**
- **Unit (golden):** нормализация Markdown из разных форматов → единый вид
- **Unit (golden):** валидатор пропускает корректную задачу
- **Unit (golden):** валидатор отклоняет задачу с пустым описанием
- **Unit (golden):** нормализация с сортировкой тегов

**Сторипоинты:** 2
